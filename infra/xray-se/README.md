# Швеция

Публичное имя `xrayse.vpn.mozhno.org` указывает напрямую на `en_proxy`. Три продукта используют отдельные входы VLESS/XHTTP/REALITY и индивидуальные ключи. Клуб использует 443/tcp (inbound 1), платная подписка — 11443/tcp (inbound 2), роутерная — 10443/tcp (inbound 3). На входе сохранены режим packet-up, параметры XMUX и имя REALITY из проверенного личного профиля. Ключ первого личного профиля сохранён отдельно от выдачи пользователям.

На сервере используется нативная служба `x-ui.service` из официального дистрибутива 3X-UI v3.7.0. Состояние и секреты находятся в `/etc/x-ui`. Панель на TCP 2053 и внутренние подписки на TCP 2096 доступны с адреса `mozhno_bot`. HTTPS использует отдельный сертификат для шведского домена. Его открытая часть размещается на `mozhno_bot` в `/opt/mozhnobot/bot/.vpn-node-tls/sweden.pem`, путь внутри контейнера передаётся через `NODE_EXTRA_CA_CERTS`. Для бота, VPN-бота и сервиса подписок Compose задаёт соответствие имени панели её IP. При переносе узла обновить эту запись и публичную A-запись. При обновлении сертификата обновляются обе стороны и перезапускаются соответствующие службы.

Команда внутри контейнера бота — `node --import tsx src/scripts/deploy-sweden.ts <этап>`. Этап `prepare` регистрирует сервер и три входа. После сетевой проверки трёх портов и примерного профиля каждого продукта этап `stage` добавляет Швецию в конец продуктов как необязательный вход. Фоновая синхронизация сохраняет подготовленные ключи, и прежние профили доступны во время выдачи новых. Этап `provision` создаёт доступы действующим подписчикам в границах шведского узла. Этап `check` проверяет записи доступа. Этап `activate` закрепляет подготовленные входы как обязательные одной транзакцией. Этап `rollback` снимает только шведские назначения из продуктов. При полном выводе сервера остановить его VPN-службу, чтобы отозвать выданные доступы.
