# Московский адрес для CDN-профилей

29.10.2026 клубный и платный профили Yandex CDN закреплены за
`188.72.110.24:443` — проверенный адрес узла `yccdn-m9-16`.
Стандартный адрес CDN `188.72.103.4` из домашней сети выбирал
`yccdn-ruufa01ufn-1`, который возвращал 504 через пять секунд, не создавая
наблюдаемого соединения с нашим origin. Прямой московский адрес проходит
TLS и доставляет запросы до origin.

Изменяется только адрес дозвона в генерируемой подписке. TLS SNI и HTTP Host
остаются раздельными: `mozhnoclub.yc.cdn.mozhno.org` и
`paid.yc.cdn.mozhno.org`. UUID, origin-порты 8443/12443, лимиты и XHTTP-параметры
сохраняются. DNS и настройки CDN-ресурсов не меняются, платное экранирование
не включается. Обычные и роутерные профили используют прежние адреса.

Политика применяется при рендеринге и к существующим строкам каталога с
доменным адресом. Новые записи каталога сразу получают московский IP.
Изменение данных в базе для переключения не требуется.

Это ручное закрепление узла, а не настройка географии CDN у провайдера.
Яндекс может изменить доступность адреса. При отказе нужно заново проверить
узел и обновить адрес через Git; автоматического возврата к уфимскому
маршруту нет. Проверка из текущей сети не подтверждает доступность нового
IP в мобильных белых списках.

Диагностика и результаты запросов сохранены локально вне tracked tree:
`.local/diagnostics/vpn-cdn-20261029/`.
Git-точка возврата до изменения — `rollback/pre-cdn-msk-20261029`.
